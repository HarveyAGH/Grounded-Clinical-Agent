# Grounded Clinical Agent - AGENTS.md

## Build, Test, and Run Commands

### Environment & Setup
```bash
python -m venv .venv
source .venv/bin/activate
pip install -e .
```

### Corpus Ingestion (Build Vector Store)
```bash
python -m rag.ingest
```
*Parses PDFs/DOCXs/TXTs from `data/`, chunks content using Docling, generates biomedical embeddings with `abhinand/MedEmbed-small-v0.1`, and saves vectors to local Qdrant at `data/qdrant_db/`.*

### Running the Agent
- **Interactive CLI mode**:
  ```bash
  python src/agent.py
  ```
- **FastAPI REST & CopilotKit AG-UI Protocol Server**:
  ```bash
  uvicorn app.main:app --reload --port 8000
  ```
- **LangGraph API Server**:
  ```bash
  langgraph dev
  ```

### Testing & Evaluation
- **Unit Tests (Pytest)**:
  ```bash
  pytest
  ```
- **Faithfulness Benchmark Suite**:
  ```bash
  python evals/run_eval.py
  ```
- **View Historical Evaluation Ledger**:
  ```bash
  python evals/run_eval.py --show
  ```

## Top-Level Directories

- `.agents`: Local skills library for agent framework tooling (e.g., CopilotKit / AG-UI).
- `.claude`: Skill configuration directory for Claude CLI agent integrations.
- `.langgraph_api`: Persistent pickle checkpoints (`.pckl`) and vector store state generated by local LangGraph API server runs.
- `.omo`: Execution session continuation metadata and run logs created by CLI agent environments.
- `.playwright-mcp`: Console log files and page snapshot YAMLs captured during Playwright MCP browser test runs.
- `agent`: Secondary skill registry containing CopilotKit agent extensions.
- `app`: FastAPI application (`app/main.py`) exposing the LangGraph workflow via REST `/query` and CopilotKit `/ag-ui` AG-UI protocol endpoints.
- `data`: Storage for raw input documents (`PDFS`, `DOCX`, `TXT`), parsed markdown (`raw`), and local Qdrant vector database (`qdrant_db`).
- `evals`: RAG evaluation harness (`run_eval.py`, `faithfulness.py`) running Ragas with Sonnet 4.6 against 20 adversarial test cases (`adversarial_questions.json`) and logging to `benchmarks.json`.
- `grounded_clinical_agent.egg-info`: Python package metadata generated by editable pip installation (`pip install -e .`).
- `rag`: RAG pipeline modules for document parsing (`doc_parser.py`), chunking (`content_processor.py`), embedding (`vectorstore.py`), indexing (`ingest.py`), and similarity search (`retrieval.py`).
- `src`: Main LangGraph state graph (`agent.py`), state models (`states.py`), Qdrant tools (`tools.py`), and system prompt markdown files (`prompts/`).
- `tests`: Pytest suite (`test_faithfulness.py`) verifying evaluation harness fallbacks.

## Non-Standard & Surprising Implementation Details

1. **Dual LLM Configuration (Agent vs. Judge)**:
   - The primary agent node uses AWS Bedrock Claude Haiku 4.5 (`global.anthropic.claude-haiku-4-5-20251001-v1:0`) at `temperature=0` for deterministic outputs.
   - The Ragas evaluation judge uses Claude Sonnet 4.6 (`global.anthropic.claude-sonnet-4-6`). Both use Bedrock's `global.` inference profile prefix. The judge model is intentionally separated from the agent model to prevent self-preference bias during evaluation.

2. **Self-Correction Verification Loop**:
   - Every medical answer generated by the agent passes through an internal `groundness_checker` node (`src/agent.py`).
   - If claims are unverified against retrieved Qdrant chunks, the graph feeds feedback back to `medical_agent_node` for up to 3 retries before escalating to human review (`eval_fallback_node`).
   - Refusals, disclaimers, and limitation statements are explicitly excluded from groundness verification to avoid penalizing proper clinical safety refusals.

3. **Biomedical-Specific Vector Embeddings**:
   - Vector storage (`rag/vectorstore.py`) uses HuggingFace `abhinand/MedEmbed-small-v0.1` locally with Qdrant, specifically chosen over general-purpose embeddings to accurately capture clinical terminology (*edentulism*, *caries*, *amoxicillin prophylaxis*).

4. **External Postgres Checkpointer**:
   - The compiled LangGraph graph (`src/agent.py`) uses `PostgresSaver` backed by a remote Neon PostgreSQL database (`DB_URI` in `.env`) rather than in-memory state, persisting graph execution threads across runs.

5. **Prompt File Decoupling**:
   - System prompts are stored as external markdown files in `src/prompts/` (e.g. `AgentDecisionSystemPrompt.md`, `MedicalSystemMessage.md`) and loaded dynamically at runtime rather than hardcoded in Python modules.

6. **Protocol Endpoint Dual-Mounting**:
   - `app/main.py` uses `ag_ui_langgraph` to expose the LangGraph agent over CopilotKit's AG-UI protocol at `/ag-ui` while simultaneously offering a simple FastAPI REST endpoint at `/query`.
